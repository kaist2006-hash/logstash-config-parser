# NICE 120바이트 헤더 파서 검증 보고서

## 결론

Logstash 8.17.6 기준으로 공통 120바이트 헤더 파서는 운영 반영 가능한 수준으로 검증됐습니다. 단, ES 저장을 시작하기 전 `frontback_detail.mapping.json`을 기존 템플릿에 병합해야 합니다.

## 검증 결과

| 항목 | 결과 |
|---|---:|
| Logstash 설정 문법 | 통과 |
| 합성 계약 | 8/8 통과 |
| BackChannel 거래행 | 24,715 |
| FrontChannel 거래행 | 992 |
| 전체 거래행 | 25,707 |
| ok | 25,707 |
| warning / failed | 0 / 0 |
| parser error | 0 |
| message/path 변경 | 0 / 0 |
| nice number 불일치 | 0 |

원본 로그 파일 해시와 물리 행 수도 1-worker와 4-worker 실행에서 동일했습니다.

## 동시성 검증

| 실행 | 처리 건수 | 시간 | digest_sum | digest_xor |
|---|---:|---:|---|---|
| 1 worker | 25,707 | 6.297초 | `71e3b624...45f55` | `14831dd5...1dec7` |
| 4 workers | 25,707 | 4.462초 | `71e3b624...45f55` | `14831dd5...1dec7` |

두 실행의 전체 결과 digest가 동일하므로 공유 상태 경쟁이나 워커별 결과 차이가 없습니다. 시간은 로컬 오프라인 재생값이며 운영 처리량 보증치는 아닙니다.

## 안전성·최적화 검토

- `dissect` 대신 고정폭 byte offset을 사용합니다.
- JSON은 시작 시 한 번만 읽고 필드 중복·공백·범위·120바이트 전체 커버를 검증합니다.
- 매 이벤트에서는 최대 512바이트 외피와 120바이트 헤더만 복사합니다.
- offset 120 이후 본문은 접근하거나 파생 필드로 복제하지 않습니다.
- 정규식은 로그 외피 시작점에 고정되어 있고 전문 전체를 캡처하지 않습니다.
- 최대 메시지 크기는 128KiB로 제한합니다.
- 예외·짧은 전문·비ASCII 헤더에서도 이벤트를 버리지 않습니다.
- 원본 `message`, 파일 경로, 라우팅 alias를 변경하지 않습니다.
- 민감 식별자는 검증 문서에서 마스킹했습니다.

## 검증 한계와 운영 조건

- Beats 및 Elasticsearch 연결 시험은 요청 범위에서 제외했습니다.
- 운영 Filebeat의 multiline·문자열 변환 방식은 내부망 canary에서 확인해야 합니다.
- 기존 인덱스 템플릿에 명시적 매핑을 먼저 병합해야 합니다.
- 로그 유실 방지를 위해 운영 초기에는 실패·경고 태그를 모니터링해야 합니다.
- offset 120 이후 본문 상세 파싱은 검증된 별도 규격이 생길 때까지 적용하지 않습니다.
