# Front/Back 채널 파서 검증 보고서

검증 대상은 제공받은 `FrontChannelMgr`·`BackChannelMgr` 원시 로그와 Logstash 8.17.6입니다. Beats와 Elasticsearch에는 접속하지 않았습니다.

## 결론

- 최종 `frontback.conf` 문법 검사: 통과
- 실제 `LogStash::Event` 기반 합성 계약 테스트: 8/8 통과
- 실로그 거래행: 25,707건 전부 이벤트 유지 및 공통 헤더 파싱
- 파싱 실패·예외: 0건
- 원본 `message` 변경: 0건
- 파일 경로 변경: 0건
- 로그 헤더의 `nice_number`와 전문 상관키 불일치: 0건
- 1-worker와 4-worker 결과 digest: 일치

## 입력 범위

| 파일 | 물리 행 | 거래행 |
|---|---:|---:|
| BackChannelMgr.log.2025-08-28-14 | 64,602 | 24,715 |
| FrontChannelMgr.log.2025-06-18 | 1,490 | 992 |
| 합계 | 66,092 | 25,707 |

거래행은 `[BC --> BT]`, `[BC <-- BT]`, `[FT --> FC]`, `[FT <-- FC]` 표식이 있는 행입니다. 스택 트레이스·상태 로그·부가 행은 파서가 변경하지 않습니다.

## 결과 상태

| 상태 | 건수 | 의미 |
|---|---:|---|
| ok | 25,706 | 검증된 공통 헤더 경계와 상관키 정상 |
| warning | 1 | Front 요청의 116~119 위치가 일반값 `8373`이 아닌 공백 |
| failed | 0 | 공통 헤더를 읽을 수 없는 거래행 없음 |

경고 1건은 필드를 이동해 추정하지 않았습니다. 그대로 `unexpected_front_request_code`를 남겨 후속 규격 확인 대상으로 분리했습니다.

## 내부 전문 분류

| 분류 | 건수 |
|---|---:|
| ISO8583 ASCII 후보 | 11,819 |
| ISO8583 binary/STX | 8,656 |
| custom/opaque | 3,757 |
| Front 고정폭 | 992 |
| 3HDR 고정 텍스트 | 475 |
| 테스트 텍스트 | 8 |

이 분류는 내부 전문의 형식을 식별한 것이며, ISO8583 비트 필드나 업무별 본문까지 정상 해석됐다는 뜻은 아닙니다.

## 문서 대조 결과

`taps.7z`에서 APK를 제외한 234개 파일을 조사했습니다. 독립된 Front/Back 공통 채널 규격서는 찾지 못했습니다. 다음 두 XLS에는 두 매니저의 실제 로그 예시와 특정 S-OIL 업무의 512-byte 상위전문 필드표가 존재했습니다.

- `20250120_NASR2412-01466_SOIL모바일쿠폰46및세차쿠폰.xls`
- `20250205_NASR2412-01466_SOIL세차쿠폰발급사명변경.xls`

이 자료는 특정 업무 개발·테스트 문서이므로 전체 채널 규격으로 적용하지 않았습니다. 제공 Back 로그에는 해당 S-OIL 상위전문을 검증할 충분한 표본도 없습니다. JSON에는 후보를 `enabled: false`로 기록했습니다.

## 동시성·안전성

동일한 파서 인스턴스를 4개 작업 스레드가 공유하는 조건으로 전체 로그를 재생했습니다. 1-worker와 4-worker의 `digest_sum` 및 `digest_xor`가 모두 일치했고, 이벤트·경로·상관키 변경도 없었습니다. JSON은 `register`에서 한 번 읽고 재귀적으로 동결되며 이벤트 처리 중 파일 I/O나 네트워크 호출은 없습니다.

## 검증 한계

- 운영 Filebeat/Beats의 실제 문자 디코딩 경로는 내부망에서 확인하지 않았습니다.
- ES 인덱스 저장·매핑 적용은 요청 범위에서 제외했습니다.
- 결제 내부 전문 원문, PAN·Track2·PIN 등 민감값은 검증 보고서나 저장소에 포함하지 않았습니다.
- 카드사·업무별 내부 상세 파싱은 해당 selector와 실로그 표본을 추가한 뒤 별도 활성화해야 합니다.
