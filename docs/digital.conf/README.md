# digital.conf 진행 현황

업데이트: 2026-10-18

## 파일

- [digital.conf](../../digital.conf): 신규 epay 요청·응답 처리 보완본을 포함한 전체 설정.
- [설정 가이드](GUIDE.md): 코드 조각, 그룹별 동작, 보완 전후 차이.
- [검증 요약](VALIDATION.md): 완료한 검증과 미검증 범위.

## 반영한 내용

- 기존 Beats input, VAN grok 파싱 및 output 구조 유지.
- epay.out 파일에서 REQUEST DATA 하위 URL과 POST RESPONSE DATA 하위 JSON만 위치 기준으로 선택.
- 요청 grok + kv, 응답 본문 조합 + JSON 파싱, 응답 첫 객체의 TR_ID URL 인코딩.
- 응답 일반 로그 혼입 감지, 본문 1MiB 상한, JSON 실패 이벤트 제외.

## 공개본과 로컬 원본의 차이

접속 password 4곳만 임시값 `00000000`으로 변경했습니다. 사용자 요청에 따라 접속 주소·계정·인덱스 이름은 유지했습니다. 임시값은 실제 운영 비밀번호가 아니며 공개된 예시값입니다. 운영 비밀번호로 사용하지 마세요.

원본 로그, 거래 식별자·거래값이 포함된 상세 검증 결과, 화면 사진은 이번 업로드에서 제외했습니다. 로컬 원본 파일과 기존 저장소의 다른 설정은 변경하지 않았습니다.

## 운영 적용 전제

해당 파이프라인에 `pipeline.workers: 1`, `pipeline.ordered: true`가 필요합니다. 이 두 값은 digital.conf 안에 자동 적용되지 않으므로 파이프라인 설정에서 별도로 확인해야 합니다.

기존 worker 2 파이프라인에 그대로 적용하는 설정이 아닙니다. worker 변경은 기존 VAN 처리량에도 영향을 줄 수 있습니다. 원본 입력 순서·구간 누락·교차 문제를 복구하거나 재전송 중복을 제거하지 않습니다.

비밀번호는 운영 환경에서 안전하게 별도 설정하고, 기존 테스트용 output 목적지·인덱스도 확인해야 합니다. 실제 설치 버전의 문법 검사, 재수집 및 기존 VAN 동시 부하 시험 후 적용하세요.

이 커밋은 GitHub에 진행 내용을 기록한 것이며 운영 서버 배포나 운영 안전성 인증이 아닙니다.
