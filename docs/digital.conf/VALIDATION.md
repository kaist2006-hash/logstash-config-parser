첨부 실로그 377,805줄을 원래 순서대로 읽어 대상 위치 선택, grok/kv 상당 처리, JSON 조합·파싱을 재현했습니다. URL 인코딩은 실제 Java URLEncoder를 사용했습니다.

보완 전·후의 정상 대상 선택 건수는 같았습니다. 34개는 수집 범위, 파일별 상태 분리, 일반 로그 혼입, JSON 오류, 크기 상한 등 별도로 만든 상황입니다. 제외해야 할 이벤트를 제외한 것도 통과입니다. 비정상 본문을 복구한다는 뜻은 아닙니다.

## 검증의 한계

- 실제 Logstash/JRuby 실행이 아니라 오프라인 재현입니다.
- 실제 서버에서의 전체 문법 검사, 동시 처리, 운영 부하 검증은 이 결과에 포함되지 않습니다.
- 입력 순서·구간이 유지되는 전제이며 worker 2에서의 안전성을 보장하지 않습니다.
- TR_ID 표현을 맞추는 것이지 요청·응답을 일대일 결합하는 설정은 아닙니다.
- 공개 요약에는 실거래값과 원본 로그를 넣지 않았습니다.

## GitHub 공개본 점검

- 업로드 설정은 로컬 최신 보완본에서 password 4곳만 `00000000`으로 치환합니다.
- 주소·계정·필터·기존 output 구조는 그대로 유지합니다.
- 이번 업로드가 새로운 Logstash 재실행 시험을 의미하지 않습니다.
