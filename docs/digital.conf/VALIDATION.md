# 최종 OUTBOUND 설정 검증

검사일: 2026-10-29

## 대상과 검사 방법

최신 첨부 catalina.out의 172,354바이트, 1,229개 물리적 줄을 CP949 strict로 읽었습니다. 원본 파일과 실제 거래값은 공개 저장소에 올리지 않았습니다. 파일명을 검사 환경에서 바꾼 것이 아니라, 내용은 같은 상태에서 실제 운영/테스트 원본 경로가 /epay/ 조건과 일치한다는 전제로 신규 메시지 선택을 재현했습니다.

최종 digital.conf의 두 grok 패턴을 직접 추출하고 관련 grok 정의를 확장해 Python 정규식으로 검사했습니다. 요청의 kv 결과는 원문 key=value 전체와 대조했고, 응답 JSON 객체는 원문 객체와 비교했습니다. 시간 문자열은 yyyy-MM-dd HH:mm:ss,SSS 형식 확인 후 Asia/Seoul(+09:00, 해당 날짜) 해석과 UTC 변환을 재현했습니다.

**Python 재현 검사이며 Logstash/JRuby/Oniguruma 네이티브 실행이 아닙니다.** 정적 괄호·문자열 균형 검사는 Logstash -t를 대신하지 않습니다.

## 별도 형식 확인

실제 로그를 바탕으로 다음 6개 wrapper 변형을 검사했습니다. 이 수치는 실로그 대상 4건에 더해 수집 건수로 합산하지 않습니다.

- 요청: 원래 형식 / 끝 대괄호 한 개 추가 / 마커 앞 대괄호 한 개 추가.
- 응답: 원래 형식 / 마지막 표시용 대괄호 생략 / 마커 앞 대괄호 한 개 추가.

6개 모두 본문 내용이 변형 없이 추출됐습니다.

## 기존 설정 보존

- 기존 VAN 정규식 48개 유지. 직전 GitHub 버전의 VAN 정규식 문자열 48개와도 동일함을 비교.
- 첨부 적용본의 VAN 및 공통 필터 본문 보존.
- beats 포트 9900, Elasticsearch 호스트·사용자·기존 인덱스 설정 유지.
- 신규 Elasticsearch 파일 조건만 필터와 동일하게 /epay/로 맞춤.
- 비밀번호 네 곳만 공개용 00000000으로 대체.
- 기존처럼 별도의 LPAY 전용 output은 추가하지 않음.

## 시간 동작

최종 date target은 log_timestamp입니다. @timestamp에 복사하는 코드는 없습니다. log_timestamp가 날짜 값으로 직렬화되어도 이미 존재하는 Elasticsearch text 매핑이 date로 바뀌지는 않습니다. 기존 인덱스 매핑 적용 여부는 본 검사에서 확인하지 않았습니다.

이전 문제에서 사용자가 Elasticsearch 미표시 원인이 조회 시간 차이였음을 확인했습니다. 이는 이번 최종 파일의 Elasticsearch 색인 시험 완료와는 별개의 기록입니다.

## 아직 수행하지 않은 검증

- 실제 Logstash 설정 컴파일과 플러그인 실행.
- 실제 Elasticsearch 매핑·템플릿 검사 및 색인 시험.
- 운영 전체 파이프라인의 CPU/메모리/처리량 부하 시험.
- 모든 업체·향후 모든 가변 데이터에 대한 보장.
- Filebeat 재전송의 영구 중복 제거.
