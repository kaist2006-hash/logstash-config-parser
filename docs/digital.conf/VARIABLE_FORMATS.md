# 가변 형식 지원 범위

확인일: 2026-10-26 · 기준: REQUEST DATA + RESULT DATA 현재 설정

## 1. 무엇을 가변적으로 받는가?

요청 grok은 URL과 query 문자열을 분리합니다. 각 업무 필드의 이름·순서·개수는 kv가 처리합니다. 응답 grok은 JSON 본문 전체를 분리하며 필드·중첩 구조는 JSON 플러그인이 처리합니다.

따라서 업무 필드가 바뀔 때마다 grok 패턴에 필드 이름을 나열해 추가할 필요는 없습니다. 반면 구간 제목과 구분선·본문의 배치, 파일명·날짜 경계 같은 바깥 형식은 정해진 조건을 사용합니다.

## 2. 지원되는 변화

| 변화 | 현재 동작 |
|---|---|
| 요청 URL의 도메인·경로·값 변경 | 추출 가능. query 구분자로 쓰는 첫 & 또는 ? 앞을 URL로 분리 |
| 요청 query 필드 추가·삭제·순서 변경 | kv로 추출. 특정 RESULT_CODE·TR_ID 존재를 필수로 하지 않음 |
| 첫 query 구분자 ? 또는 & | 둘 다 허용 |
| query 없는 URL | URL만 추출, kv 생략 |
| KEY= 빈 값 | 빈 문자열로 보존 |
| 값의 %26·%3D·%2B 같은 인코딩 | 요청에서는 그대로 유지 |
| 값 안의 = 문자 | 확인한 ABC== 같은 형태는 보존 |
| 응답 JSON 키 이름·순서·개수 변경 | 유효한 JSON이면 구조대로 파싱 |
| 응답 중첩 객체·배열 | 구조대로 파싱. EPayReturnReq 포함 |
| 한 줄 JSON / 들여쓰기·줄바꿈 JSON | Filebeat가 완성된 한 이벤트로 합친 경우 처리 |
| 빈 응답 배열 [] | 그대로 보존 |
| LF·CRLF | 처리 |
| 별표 개수 변화, 별표 행 앞뒤 공백·탭 | 처리 |
| 종료 별표 행 반복 | 첫 종료 구분선까지만 본문 추출 |

필드가 늘면 Elasticsearch 매핑도 늘 수 있습니다. 원문 파싱 성공과 Elasticsearch 색인 성공은 별개입니다. 같은 경로의 필드가 문자열에서 객체로 바뀌는 등 기존 매핑과 충돌하는 타입 변화는 색인 단계에서 문제가 될 수 있습니다.

## 3. 자동 수용을 보장하지 않는 변화

| 변화 | 필요한 확인 |
|---|---|
| REQUEST DATA / RESULT DATA 제목 변경·앞뒤 공백·들여쓰기 | Filebeat include_lines와 grok을 함께 수정해야 함 |
| URL 행 앞에 공백·다른 접두사 추가 | 현재 [url= 시작 패턴에 맞춰 수정 필요 |
| 제목·별표·본문의 순서 변경 또는 필수 구분선 누락 | 현재 구간 추출 조건 변경 필요 |
| Filebeat 날짜 시작 형식 변경 | multiline 경계 정규식 검토 필요 |
| 파일명 epay.out 변경 | input paths와 Logstash 파일 조건 동시 검토 |
| query 값에 구분 의미가 아닌 원문 & 사용 | kv는 항목 구분자로 해석. 값에서는 %26 같은 적절한 인코딩 필요 |
| 요청 URL에 실제 개행이 들어감 | 한 줄 URL 전제 밖이므로 값의 정확성을 별도 확인 |
| JSON 문법 오류 또는 timeout으로 잘린 JSON | 현재 실패 이벤트 제외 대상 |
| JSON 최상위가 배열에서 객체로 변경 | JSON 자체는 파싱 가능하나 TR_ID의 [0] 접근은 수정해야 함 |
| 응답 배열에 여러 객체 | 전체 파싱되지만 TR_ID 인코딩은 첫 객체에만 적용 |
| TR_ID가 tr_ID 등 다른 이름으로 변경 | JSON 필드는 추출되지만 현재 인코딩 대상에는 해당하지 않음 |
| 응답 TR_ID가 이미 URL 인코딩됨 | 현재는 다시 인코딩하므로 %가 %25로 바뀔 수 있음 |

## 4. 확인한 사례

현재 grok 패턴에 대해 추가로 다음 12개 형식을 오프라인 검사했습니다. 처리할 형식은 예상대로 추출하고, 지원하지 않는 제목·들여쓰기는 예상대로 제외되는지 확인했습니다.

1. 요청 도메인·경로와 업무 키 변경.
2. 요청 키 순서 변경·일부 키 누락.
3. ? 구분자.
4. %26 값·값 내부 =·빈 값.
5. 다른 응답 키.
6. 중첩 객체·배열.
7. 여러 줄·들여쓰기 JSON.
8. 별표 개수·앞뒤 공백 변경.
9. 두 객체 JSON 배열 파싱.
10. 바뀐 제목 제외.
11. 제목 앞 공백 제외.
12. URL 행 앞 공백 제외.

12개 모두 예상 결과와 일치했습니다. 새 사례 검사는 grok·kv 상당 처리와 JSON 파싱 범위입니다. 합성 사례의 Ruby 인코딩·실제 Filebeat 필터·실제 Logstash 실행을 새로 검증한 것은 아닙니다. 기존 실로그에 대한 1,056건 요청·946건 응답 재현 및 Java 인코딩 검증과 구분합니다.
