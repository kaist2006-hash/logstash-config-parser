# 현재 형식의 가변 범위

확인일: 2026-10-29. 대상은 시간과 본문이 같은 줄에 있는 OUTBOUND 로그입니다.

## 수용 범위

- 요청 파라미터 이름·순서·개수 변화: key=value 구조와 & 구분자를 유지하면 kv가 처리.
- 빈 요청 값: allow_empty_values true + whitespace strict로 보존.
- 요청 값의 = 문자: 키 뒤의 값에 남아 있는 =는 보존. 첨부 정상값 전체를 비교 검증.
- URL에 파라미터가 없는 경우: URL만 추출하며 request_data는 생성되지 않을 수 있음.
- 괄호를 포함한 요청 값: include_brackets false로 (), [], <>의 자동 wrapper 제거를 하지 않음.
- 요청 마커 앞 대괄호 1개 또는 2개 허용.
- 요청 뒤 닫는 대괄호 1개 또는 2개 허용. 본문 query는 닫는 표시와 분리.
- 응답의 표시용 마지막 ]는 있어도 없어도 허용.
- 응답 JSON 키 순서·개수 변화: 객체 전체를 JSON 플러그인으로 파싱.
- 중첩 JSON·배열 값: 객체 내부 값은 JSON 구조대로 처리.
- CRLF의 잔여 CR 허용.
- 헤더 TR_ID 값의 길이는 고정하지 않음. UUID/영숫자 등 문자열로 보존.
- 레벨과 로거를 loglevel / logger에 저장.

## 고정 전제

- 한 이벤트 안에 시간·로그 레벨·[로거]·OUTBOUND 마커·헤더·본문이 모두 존재해야 함.
- 시간 형식은 yyyy-MM-dd HH:mm:ss,SSS. grok의 TIMESTAMP_ISO8601이 더 넓은 형식을 인식해도 date는 이 형식을 사용.
- 마커는 정확히 OUTBOUND REQUEST DATA 또는 OUTBOUND RESULT TO JSON DATA.
- 헤더 순서는 [PARTNER_CODE:...][TR_ID:...]로 고정.
- 요청 payload는 [url=URL&key=value...] 구조이며 현재는 첫 &에서 URL과 query를 분리.
- 값 안에 구분자로 사용한 raw &가 있다면 원래 파라미터 경계와 구분할 수 없으므로 로깅 시 인코딩 등 명확한 구분이 필요.
- 응답은 표시용 [ 뒤에 {로 시작하는 JSON 객체 하나가 완성돼 있어야 함.
- 실제 멀티라인이나 외곽 다중 객체 배열은 이번 설정에서 보장하지 않음.
- 임의의 비정상 JSON/query 또는 업체별 매핑 타입 충돌까지 보장하는 것은 아님.

## TR_ID 구분

최상위 TR_ID는 앞부분 공통 헤더 값입니다. request_data.TR_ID는 URL 파라미터의 거래값, result_data.TR_ID는 JSON 거래값입니다. 현재 헤더 값은 요청·응답 2쌍 모두 일치합니다. 본문은 인코딩/디코딩 차이가 있을 수 있으며 값을 임의로 변환하거나 교환하지 않습니다.

## 검증 한계

실로그 4건과 6개 대괄호 변형을 오프라인으로 검증했습니다. 로그 형태가 고정 전제에서 벗어나거나 새 업체 값의 Elasticsearch 타입이 충돌하는 경우에는 추가 검증이 필요합니다. 처리량·메모리 부하 시험은 수행하지 않았습니다.
