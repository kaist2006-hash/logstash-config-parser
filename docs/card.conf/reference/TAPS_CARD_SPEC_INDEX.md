## 롯데 MS — 기존 미정의 F57/F61 매칭 결과

현재 `lotte_ms` 파서가 일부 실로그에서 `unknown_field`로 멈춘 F57/F61은 TAPS 압축 안의 더 최신 롯데 MS 전문에서 확인됐다.

### 2025-06-15 원시로그에 가장 적합한 기준 문서

`CRD/롯데카드-33,38/롯데카드 VAN MS 전문_20230321.xlsx`

SHA256: `ce9d8266d89d1745857fece87434f13a37f6dc1756082feb3aa573e36ab552e9`

이 문서는 테스트 원시로그 `GCLTC_X25A_P01.06152025.12.log`의 날짜(2025-06-15)보다 이전 버전이므로, 이후 문서보다 우선해서 실제 로그 규격과 대조하기 좋다.

### F57

- BIT: `57`
- 항목: `DEPOSIT-INFO`
- TYPE: `CHAR`
- 전체 LEN: `19`
- 구조: `길이 3("016") + 보증금매출 구분값 2Byte("SB") + 보증금금액 14Byte`
- 샘플: `016SB00000000001000`

현재 파서 표현으로는 **ASCII 3자리 length prefix + payload 16 bytes** 형태로 해석하는 후보가 된다.

### F61

- BIT: `61`
- 항목: `ARTCL_INFO`
- TYPE: `CHAR`
- LEN: `234`
- 구조: `물품분류수<4> + ((물품구매건수<4> + 물품코드<4> + 물품코드별금액<15>) * 10)`
- 물품코드 예: `1110` 기저귀, `1210` 분유, `3110` 위생용품
- 바우처 거래에서 설정됨

표의 세부 길이 합계가 `4 + (4+4+15)*10 = 234`이므로 F61은 문서상 **234-byte 고정 길이 필드 후보**로 읽힌다.
