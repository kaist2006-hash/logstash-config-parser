# CARD FINAL20 적용 안내

문서 갱신: 2026-11-06. 파서 식별자: `2026-11-04.final20`.

## 이번 변경

일반 등록 ISO 금융전문에서 처리코드·금액·전송일시가 모두 유효하면 공통 fallback이 가능합니다. 관리 MTI 0800/0810은 문맥 필드(일시·관리코드 등) 1개와 식별 필드(추적·참조·단말·가맹점 등) 1개 이상을 요구합니다. 이때 실제 공통 출력으로 보관할 수 있는 필드만 최소조건의 증거로 셉니다.

공통 최소조건을 충족하지 못하면 error를 유지합니다. FINAL19에서 전부 제거하던 업무 값 중, 완전히 읽혀 검증된 공통 필드만 FINAL20에서는 남깁니다. 미완성·잘못된 값과 상세 전용 필드·EMV·rest는 남기지 않습니다. 파서 내부 예외가 발생하면 공통 업무 값도 보존하지 않습니다.

JSON의 `error_policy.preserve_validated_common_fields: true`가 이 보존 정책입니다. 기존 card.conf의 Ruby 필터와 script_params는 그대로 사용할 수 있습니다. RB와 JSON은 함께 교체하고 파이프라인을 재시작합니다.

```logstash
ruby {
  id => "card_detail_parser"
  path => "${CARD_PARSER_DIR}/card_detail_parser.rb"
  script_params => {
    "specs_path" => "${CARD_PARSER_DIR}/card_detail_specs.json"
  }
}
```

gateway에 의한 카드사 선택, 카드사별 필드 규격, get/put 및 IC HEX의 IN/OUT, 기존 숫자 변환, Filebeat euc-kr / JSON CP949, 농협 rest 정책은 유지합니다. 이전의 파일 경로별 alias 분기는 FINAL19부터 제거한 상태를 사용합니다. 참고 conf는 운영 input/output을 통째로 대체하는 용도가 아닙니다.

## 사진의 농협 MS

사진은 0810 통신망 관리 응답입니다. 해당 reserved 레이아웃은 ISO 기준 위치 +108의 전송일시(14B), +122의 추적번호(6B), +128의 망관리코드(3B)를 확인합니다. 세 값이 확보되어 `network_layout_common_only` 경고와 fallback으로 출력됩니다. 관리전문에는 금융전문의 거래금액을 필수로 요구하지 않습니다.

전송일시만 온전히 읽히고 추적번호도 확보하지 못한 잘린 사례는 error입니다. 이때 읽힌 전송일시는 fields에 남기지만, 잘린 추적번호를 추정해서 만들지는 않습니다.

## 엑셀 읽는 방법

전체 공통 기준 시트와 16개 IC/MS/통합 프로필 시트로 구성합니다. 각 프로필은 공통 보관 목록, 요청 OUT, 응답 IN 순서입니다. 요청/응답 목록은 JSON상 방향이 허용되는 조건부 출력 필드이며 매 이벤트에서 항상 존재한다는 뜻은 아닙니다.

실로그 관측 건수는 프로필 내 동일 ES 필드명의 방향별 합계입니다. 여러 DE·전문 변형에 같은 ES 이름을 쓰면 특정 변형의 건수로 해석하면 안 됩니다. BC MS 통합처럼 해당 실로그가 없는 경우는 별도로 표시했습니다. 미확정 내부 위치·필드 의미를 추정하지 않았습니다.

## 검증

- 69개 경계 시험: 16개 프로필의 짧은 공통값, 잘못된 필수값, 농협 관리 응답/잘림, 상세 전용 식별값을 공통 증거로 세지 않는 조건을 확인했습니다.
- 기존 계약 447개(BC 319 / BGF 분류 12 / ISP 53 / 롯데 IC 20 / 출력 43), 삼성 가변 160개·음성 경계 7개, 인코딩 경계 11개를 통과했습니다.
- 제공 수집 대상 1,291,227건 재생: ok 1,200,953 / fallback 75,394 / control 14,880 / error 0. FINAL19 대비 각 원본의 상태·출력값 개수·rest 건수 차이 0입니다.
- 엑셀 17개 시트, 32개 방향별 목록을 JSON과 대조했습니다. 50개 구역을 렌더해 레이아웃을 확인했습니다.

실로그 재생은 로컬 Logstash 8.17.6 기준입니다. 실제 운영 Filebeat→Elasticsearch에 접속한 검증은 아닙니다. 정상 제공 로그의 error 0 결과와 별개로, 손상·심한 잘림 시험에서는 error가 유지됩니다.

현재 규격은 BC BCA/EPT 내부 상세와 BC MS 통합 실로그 등 기존의 지원 한계를 유지합니다. BC BCA/EPT는 확인된 외부 공통 헤더만 fallback입니다. 농협에서 정의된 상세필드를 다 해석한 뒤 남은 바이트만 rest로 묶으며, 다른 카드사나 필드 도중 손상에 이 처리를 확대하지 않았습니다.
