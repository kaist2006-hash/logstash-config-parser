# 고정 규격과 가변 데이터 처리 — FINAL17

특정 실로그의 금액·시간·참조번호·응답코드·가맹점번호·linename·행 번호를 운영 예외 조건으로 사용하지 않습니다.

| 구분 | 처리 |
|---|---|
| 고정 길이 필드 | 문서의 자리수만 고정합니다. 값은 매 이벤트에서 읽습니다. 선행 0을 보존합니다. |
| LLVAR/LLLVAR | 실제 길이 접두값을 읽고 해당 길이만 소비합니다. 다음 필드 위치는 누적한 바이트 수로 계산합니다. |
| 비트맵 | 실제 설정 비트에 있는 필드만 순서대로 읽습니다. 선택 필드의 유무가 바뀌어도 샘플 위치를 사용하지 않습니다. |
| 문자·BCD | 프로필의 단위와 인코딩에 따라 바이트 수를 계산합니다. 문자 개수로 바이트 위치를 추정하지 않습니다. |
| MTI·헤더 | 해당 카드사 JSON에 정의된 조합을 사용합니다. 다른 카드사의 규격을 빌려 쓰지 않습니다. |
| 전문 길이 | `len[n]` 또는 계수된 `put_msg_complete[...][n]`에서 매 이벤트의 n을 읽습니다. 특정 샘플 길이를 고정하지 않습니다. |
| 로깅 문구 | uid·linename의 값과 길이는 가변입니다. logger 문구를 ISO 데이터에서 분리합니다. |
| 전송 종료 구간 | 삼성의 계수된 요청에서 확인한 `FF EF` 규칙만 적용합니다. 종료 위치가 맞지 않으면 손실을 숨기지 않습니다. |
| 알 수 없는 변형 | 근거가 있는 공통 필드만 fallback으로 출력합니다. 공통 값도 안전하게 검증하지 못하면 error입니다. |

16개 프로필에는 가변 길이 DE 정의가 144개 있습니다. 정의가 있다는 이유만으로 미관측 조합까지 검증됐다고 보지 않습니다. 삼성 MS는 값·LLVAR/LLLVAR 길이·선택 비트·헤더·MTI를 바꾼 160개 조합을 실제 필터로 검사했습니다. 다른 카드사는 제공된 전체 실로그로 재검증했습니다.

길이 접두값이 규격 최대를 넘거나, 숫자 접두부가 공백·마스킹으로 유실되면 다음 위치를 추정하지 않습니다. 문서가 최대 6자리로 정의한 필드를 임의로 11자리까지 허용하는 식으로 완화하지 않습니다.

NH의 특수 통신망 복구는 확인된 레이아웃 서명에서만 적용합니다. 다른 비트맵·예약영역으로 바뀐 포맷을 같은 위치로 강제 해석하지 않습니다. NH의 알려진 후행 데이터 rest 정책과 다른 카드사의 후행 데이터 정책도 그대로 유지합니다.

JSON의 `numeric`은 숫자 문자 검증 옵션입니다. Ruby 업무 필드는 문자열로 출력하며 Elasticsearch의 숫자형 변환은 conf/mapping에서 별도로 결정합니다.
