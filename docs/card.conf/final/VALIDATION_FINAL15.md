# FINAL15 검증 결과 — 2026-10-30

> FINAL16에서 롯데 MS·국민 IC 헤더와 농협 망관리 공통 배치를 복구했다. 삼성 사진의 BC 원본 혼입도 구분했다. 현재 결과는 [FINAL16 검증서](VALIDATION_FINAL16.md)를 따른다. 아래는 이전 버전 이력이다. FINAL15의 “117건 모두 헤더 없음”과 “농협 142건 심한 절단” 설명은 잘못이었다. 실제 헤더 변형과 예약영역 망관리 배치를 새 검증서에서 정정했다.

BGF와 같은 취지로 분류를 수정했습니다. **공통 구간을 검증할 수 있지만 상세 규격을 끝까지 해석하지 못하면 공통필드만 추출하고 fallback**, 공통 구간조차 확인할 수 없거나 식별에 필요한 입력이 현저히 부족하면 error입니다. 이 분류는 수집 로그의 복구 가능성을 나타냅니다.

## 분류와 출력

| status | 판정과 출력 | 이 파서가 추가하는 tags |
|---|---|---|
| ok | 구현된 프로필 규칙으로 완료. 공통·선택 상세 필드 출력 | 없음 |
| fallback | 공통 구간 확인 후 상세 불일치·길이 부족·디코딩 손실 등. 검증된 공통필드만 출력 | fallback |
| error | 전문 식별 실패, 손상된 헤더/bitmap, 최소 공통정보 부족, 파서 예외 등. 업무 fields·emv·rest는 출력하지 않음 | error |
| control | 확인된 제어/상태 레코드. 거래 업무 필드가 없을 수 있음 | 없음 |

공통 출력 대상은 JSON의 각 프로필 emit 중 DE3~49와 extra_common_fields의 network_code입니다. 정의 위치는 카드사·IC/MS별로 독립적입니다. fallback에서는 오류 DE에서 중단하고, 이미 읽은 값 중 공통 대상만 남깁니다. 상세 DE, EMV, rest를 제거합니다. error는 업무 값을 제거합니다. errors 배열은 fallback에도 원인 코드로 남을 수 있으며 error 태그와 같은 뜻이 아닙니다. 다른 필터의 기존 tags는 지우지 않습니다.

fallback의 최소 증거는 JSON fallback_policy에 명시했습니다. 헤더·MTI·bitmap을 인식한 뒤 거래 전문은 처리코드·금액·전송일시가 각각 검증되어 있어야 합니다. 망관리 08xx는 추적번호/조회번호/단말ID/가맹점번호 중 식별값 하나와 전송일시/로컬일자/로컬시각/망관리코드 중 문맥값 하나가 필요합니다. 정상 부분이 없는 입력의 태그를 일괄 변경하지 않습니다.

### 삼성 MS F55

공백 길이 F55 1,606건 모두에서 처리코드·금액·일시·조회번호·가맹점번호·통화 등 공통 값이 확인되었습니다. 이들은 이제 **공통필드만 출력하는 fallback**입니다. F55와 후속 상세 규격 자체를 새로 해석한 것은 아닙니다. 제공 MS 규격의 F55 할부개월수는 `002 + NN`이나 해당 위치가 공백입니다. “구형”이라는 버전 판정은 하지 않습니다.

삼성 MS 최종 결과: ok 47,970 / fallback 65,166 / error 56. 남은 56건은 전문 표기와 헤더가 없는 조각 로그입니다. input_decoding_loss 같은 원인 코드가 fallback에 남아도 error 태그를 추가하지 않습니다.

### 남은 error 259건

- 117건: 전문 표기 또는 ISO 헤더를 확인하지 못한 입력. BC IC 42, 국민 IC 2, 국민 MS 6, 롯데 MS 9, 우리 통합 2, 삼성 MS 56건입니다.
- 농협 MS 142건: 망관리 0800 80건·0810 62건. 단말ID DE41에서 입력이 끊기며, 그 이전의 추적번호·조회번호 등이 비어 있고 유효한 단말/가맹점 식별값도 아직 확보되지 않았습니다. 시각 등의 일부 값만으로 식별 가능한 공통 이벤트를 만들지 않습니다. 검사 전후 업무 값은 최종 출력하지 않습니다.

헤더나 bitmap이 손상된 입력, 매우 짧은 입력, 기본 거래코드·금액·일시를 검증하지 못한 합성 음성 사례도 error로 확인했습니다.

## 검증 근거

- 실제 Logstash 8.17.6 JRuby/Event와 공유 파서 4 workers로 전 서비스 전량을 full/minimal 두 모드로 재생했습니다. 망관리 공통 판정을 보완한 뒤 영향 서비스 농협 MS 10,296건을 최종 조건으로 추가 전량 재생했습니다. 이전 복구 조건은 새 조건에 포함되며 나머지 서비스의 잔여 오류는 표기/헤더 단계이므로 결과가 변하지 않습니다. 단계와 범위는 ALL_CARD_FIELD_VERIFICATION.json에 기록했습니다.
- 모드 간 업무 값 차이, 잘못된 출력 타입, 오류 DE 이후 출력, 입력 변조, 프로필 오선택은 0건입니다. **fallback의 상세 필드 출력 0건, error의 업무 필드 출력 0건, 공통 증거 없는 fallback 0건**입니다.
- 최종 파일 그대로 specs_path만 설정한 실제 Logstash stdin/json_lines → Ruby → file 파이프라인에서 522건(실로그 표본 520 + 비정상 합성 2)을 실행했습니다. 준비한 기대 결과와 전부 일치했습니다. 삼성 F55 실사례·농협 망관리 실사례를 별도 포함했습니다. Ruby 예외와 기본 진단 필드 유출은 없습니다.
- 분류·공통/상세 경계·카드사 규격 독립성 시험 26건, 기존 분류/인코딩 계약 18건을 통과했습니다.
- 비교 가능한 14개 서비스에서 승인 요청·응답 100쌍씩 총 1,400쌍을 대조해 금액·가맹점번호·통화 차이는 없었습니다. BC IC/MS는 비교 조건을 충족한 쌍이 없어 이 시험 통과로 세지 않습니다. 국민 IC는 HOST ID 대신 문서의 국내 가맹점번호를 비교했습니다.
- 농협에서 알려진 문서 구간 뒤의 rest를 ok로 보존하는 기존 정책은 유지했습니다. rest 56,692건 / 42,004,838바이트입니다. 알려진 필드 내부 오류를 rest로 숨기지 않습니다.

## 최적화와 운영

기본 diagnostics는 minimal입니다. parser_version·bitmap·consumed_bytes·offset 같은 진단 출력을 숨기며 오류 코드와 DE 번호는 남깁니다. 버전은 비인덱싱 @metadata에 둡니다. 520개 동일 실로그 표본에서 card_detail 직렬화 크기는 full 521,287 → minimal 301,497바이트(42.16% 감소)였습니다. 이벤트 전체 크기·ES 저장량·처리량 개선율을 뜻하지 않습니다.

JSON 1회 로드·컴파일·동결, 프로필 직접 선택, 정규식/상수 사전 준비, 이벤트당 파일·네트워크 I/O 없음 등 기존 최적화를 유지했습니다. 공통 이름 집합은 시작 시 컴파일합니다. 불필요한 상세 해석의 추측이나 카드사 규격 통합은 추가하지 않았습니다.

Filebeat euc-kr을 유지하는 CP949 복원 경로를 검증했습니다. 이미 U+FFFD로 손실된 원바이트를 되살리지는 못하므로 신뢰 가능한 공통 구간만 복구합니다. 실제 Filebeat → Elasticsearch 운영 종단 시험은 수행하지 않았습니다.

## 해석 범위

BC MS의 5,776건 ok는 BCB/BCA/EPT 고정 레코드의 방향·표식·길이 확인입니다. 내부 업무 필드 문서가 없어 상세 fields는 없습니다. 롯데 IC는 제공 ASCII 실로그 경로를 검증했으며 별도 최신 binary IC까지 구현·검증한 것은 아닙니다. 미관측 필드·MTI·옵션 조합은 검증 완료로 표시하지 않습니다. 관측 수는 CARD_FIELDS_FINAL15.md에 있습니다. 전체 카드사의 모든 상세 포맷이 구현되었다는 뜻은 아닙니다.

최종 파일 SHA256은 MANIFEST_FINAL15.json 및 ALL_CARD_FIELD_VERIFICATION.json에 있습니다. 원문·실제 거래값은 보고서와 배포 ZIP에 넣지 않았습니다.
