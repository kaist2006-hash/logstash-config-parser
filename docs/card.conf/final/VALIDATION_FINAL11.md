# CARD parser FINAL11 검증

버전: `2026-10-30.final11` · 검증일: 2026-10-30.

## 결론과 시험 범위

Filebeat의 `encoding: euc-kr`을 유지하는 사용자 환경을 기준으로 JSON 기본 역변환을 `CP949`로 맞췄다. JSON만 지정하는 기존 Ruby 블록으로 이 기본값이 적용된다. 삼성 MS 실제 신규 파일을 별도 프로필로 활성화했다.

Logstash 8.17.6의 실제 JRuby와 `LogStash::Event`, 공유 파서/4개 워커로 16개 고유 자료의 전문 후보 1,208,914건을 재생했다. 각 후보를 바이트 보존 기준과 EUC-KR 호환 수집 조건으로 각각 실행했다. **EUC-KR 경로는 CP949 디코딩과 잘못된 바이트의 U+FFFD 치환을 모의한 시험이며, 실제 Filebeat부터 Elasticsearch까지 연결한 운영 시험은 아니다.**

신규 삼성 MS 파일 SHA-256: `bd71e484b9ea3bb2b09f2b3736d29b6a927edec4785fe4d08cf946270e280dd1`. 이전 `win_ms=bcc_ms` 중복 파일은 삼성 검증에서 제외했다. 신규 파일은 물리 113,192줄 중 전문 후보 56,568건이며, MTI는 승인응답 `0210` 49,387건, 취소응답 `0430` 6,937건, 통신망응답 `0810` 244건이다. 요청 전문과 이 외 MTI는 이번 파일의 실로그 검증 범위가 아니다.

## 국민 MS와 삼성 MS

국민 MS는 기존 EUC-KR 호환 재현의 error 28,907건에서 7건으로 감소했다. 현재 결과는 ok 49,637, fallback 21,658다. 기존에 전역 문자열을 Latin-1로 역변환하던 실패와 전문 밖 로거 버퍼의 치환 문자를 구분했다.

삼성 MS는 ok 47,970, fallback 8,598, error 0다. 전문 후보 전부에서 하나 이상의 업무 필드를 추출했다. `RESPDATA`를 전송 접두어로 제거하고, 삼성 전용 F127을 ASCII 3자리 길이+최대 512바이트 영역으로 소비한다. 이번에 문서를 다시 합산한 승인 하위 71항목/취소 하위 67항목은 각각 512바이트로 일치하며, 실제 완전한 해당 응답의 외부 길이도 512다. 이전의 blocked 사유는 이 응답 자료에 대해 해제했다. F127 내부의 개별 항목은 현재 선택된 출력 필드 목록에 넣지 않았으므로 별도 업무 필드로 출력하지 않는다. 상세 파싱을 했다는 설명은 정의된 emit 필드와 각 DE 경계에 대한 설명이다.

삼성 F55 `installment_months`와 F56 `approval_number`를 출력한다. 실제 출력 건수는 `SAMSUNG_FIELD_PRESENCE.json`에 있다. F90은 문서의 고정 42바이트로 정의했으나 제공된 응답 표본에는 이 필드가 없어 실로그 검증 완료로 보지 않는다.

구형 `ISO023400053/0210` 응답 1,607건은 마지막 F55 뒤 공백 11바이트가 있다. 해당 헤더·MTI·마지막 필드·정확한 길이·공백 바이트를 모두 확인한 경우에만 `legacy_space_padding` 경고와 fallback으로 처리한다. 임의의 다른 후행 데이터는 허용하지 않는다. 이 공간에서 승인번호를 만들어 내지 않는다. 0810 통신망 244건은 ISO 필드가 있는 정상 파싱 대상이므로 ok에 포함하며, BC MS의 고정 제어 레코드 control 정책을 가져오지 않는다.

## 분류 및 바이트 손실 정책

- 완전하게 복원되고 정의된 필드가 해석되면 ok다.
- 같은 규격의 짧은 전문에서 확인 가능한 업무 필드를 추출하면 fallback이다.
- EUC-KR 디코딩 중 전문 안에 U+FFFD가 생기면 최초 손실 직전의 복원 가능한 바이트만 해석한다. 업무 필드가 있고 오류가 복구 가능한 절단 오류뿐이면 fallback이다. 이후 필드는 추측하지 않으며, 모든 손실을 ok로 바꾸지 않는다.
- 헤더/비트맵을 확인할 수 없거나, 손실 이전에 잘못된 길이/필드 값 등이 발견되면 error를 유지한다.
- 독립적인 전송 길이 또는 기존의 명시적 declared-length 절단 정책으로 실제 전문 전체가 보존됨을 확인하면, 그 뒤 로거 버퍼에 생긴 손실은 파싱 실패로 취급하지 않는다. `input_loss_outside_payload=true`로 구분한다.
- `status`/`tags`는 error 또는 fallback을 사용한다. fallback의 `errors` 배열에는 `input_decoding_loss`나 절단 원인 코드가 남을 수 있다. 배열이 있다는 사실과 error 태그는 같은 뜻이 아니다.

손실 진단은 `input_text_encoding`, `input_loss_truncated`, `input_recovered_prefix_bytes`, `logged_bytes_exact=false`로 확인한다. `logged_bytes_exact=false`인 경우 logged_bytes는 복원 가능한 접두부 길이이며 원문 전체 길이로 해석하면 안 된다. 원본 message는 수정하지 않는다.

농협 rest 정책은 유지한다. 알려진 필드 전체가 처리되고 남는 데이터만 rest에 HEX로 보관해 ok로 인정한다. 수집 중 손실된 rest를 원문이라고 출력하거나 ok로 승격하지 않는다. BC MS 5,776건의 ok는 BCB/BCA/EPT 고정 레코드 구조 검증이며 내부 업무 필드 해석 완료가 아니다.

## 검증과 최적화

- 기존 오류/절단/NH rest 등 7개 계약과 신규 인코딩/로거/삼성 공백 등 10개 계약을 통과했다.
- 원본 message 변경, 공통 추출 값 불일치, 완전히 역변환 가능한 이벤트의 결과 불일치는 각각 0건이다. unexpected_parser_exception은 0건이다.
- 삼성 MS 이외의 JSON 카드사 규격은 변경하지 않았다. 바이트 보존 기준의 기존 15개 서비스의 상태별 건수는 FINAL10과 모두 일치했다.
- JSON 로딩·검증·컴파일·동결은 register에서 한 번만 수행한다. 이벤트별 파일 I/O·JSON 파싱·프로필 전체 탐색·추정 인코딩 재시도는 없다. alias 직접 조회와 바이트 오프셋 파싱, 손실 지점까지만 처리하는 방식을 유지했다.
- 실제 운영 처리량의 최적값은 장비와 pipeline 조건에 따라 다르다. 이번 두 경로 비교 재생 시간 640.094초를 운영 EPS 보장값으로 사용하지 않는다.

실제 파이프라인 스모크 결과는 `FULL_PIPELINE_SMOKE.json`에 별도 기록한다. 이 시험도 합성 입력이며 Filebeat 연결 시험을 대신하지 않는다.
